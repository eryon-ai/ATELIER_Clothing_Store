# Node.js + Express + Prisma Architecture Blueprint
**The Velocity Choice for ATELIER E-Commerce**

This document provides every detail necessary to construct the Node.js backend for the ATELIER platform from scratch.

---

## 1. Initial Setup & Libraries

**Initialization:**
```bash
mkdir atelier-backend && cd atelier-backend
npm init -y
npx tsc --init
npx prisma init
```

**Core Dependencies:**
```bash
# Core framework and ORM
npm install express cors helmet dotenv
npm install @prisma/client

# Security & Validation
npm install bcryptjs jsonwebtoken zod
npm install express-rate-limit

# Uploads & Caching (Optional based on scale)
npm install cloudinary multer redis

# Developer Dependencies
npm install -D typescript @types/node @types/express @types/bcryptjs @types/jsonwebtoken
npm install -D tsx nodemon prisma
```

## 3. Step-by-Step Implementation Details

### Step 1: Database Setup (`prisma/schema.prisma`)
Define your schema using Prisma.
- Use `String @id @default(uuid())` for primary keys.
- Use `enum` for statuses (e.g., `enum OrderStatus { PROCESSING, SHIPPED }`).
- For dynamic product variants (like "Size", "Color"), use Prisma's `Json` type: `variants Json`.
- Run `npx prisma migrate dev` to push to PostgreSQL.

### Step 2: Configuration & Validation (`src/config/env.ts`)
Never trust `.env` files blindly. Use `zod` to validate them on startup.
```typescript
import { z } from 'zod';
const envSchema = z.object({
  PORT: z.string().default('8000'),
  DATABASE_URL: z.string().url(),
  JWT_SECRET: z.string().min(32),
});
export const ENV = envSchema.parse(process.env);
```

### Step 3: Architecture Pattern (Controller -> Service -> DB)
For every module (e.g., `orders`), follow this flow:

**1. Route Definition (`order.routes.ts`):**
Defines the HTTP verb, path, and attaches middleware.
```typescript
router.post('/', requireAuth, validate(CreateOrderSchema), OrderController.create);
router.patch('/:id/status', requireAuth, requireRole('ADMIN'), OrderController.updateStatus);
```

**2. Controller (`order.controller.ts`):**
Extracts data from `req`, passes it to the service, and formats the `res`.
```typescript
export const create = async (req: Request, res: Response, next: NextFunction) => {
  try {
    const order = await OrderService.createOrder(req.user.id, req.body);
    res.status(201).json({ success: true, data: order });
  } catch (error) {
    next(error); // Passes to global error handler
  }
};
```

**3. Service (`order.service.ts`):**
Contains the actual business logic. It handles the strict ACID transactions.
```typescript
export const createOrder = async (userId: string, data: CreateOrderDTO) => {
  // Use Prisma's interactive transaction to ensure stock is deducted 
  // safely when creating the order.
  return await prisma.$transaction(async (tx) => {
    // 1. Verify stock using tx
    // 2. Deduct stock using tx
    // 3. Create Order using tx
    // 4. Create TimelineEvent using tx
  });
};
```

### Step 4: Security Middleware
Create an `auth.middleware.ts` that extracts the `Bearer token` from headers, verifies it using `jsonwebtoken`, and fetches the User from Prisma. Attach the user object to `req.user`.

Create an `rbac.middleware.ts`:
```typescript
export const requireRole = (role: string) => {
  return (req: Request, res: Response, next: NextFunction) => {
    if (req.user.role !== role && req.user.role !== 'SUPER_ADMIN') {
      return res.status(403).json({ error: 'Insufficient permissions' });
    }
    next();
  };
};
```

### Step 5: File Uploads (Images)
In your `catalog` module, use `multer` to handle `multipart/form-data`.
Instead of saving to disk, stream the buffer directly to Cloudinary using their Node SDK to avoid heavy disk I/O on your Node server. Save the returned Cloudinary secure URL in Prisma.

## 4. Deployment Strategy
1. Add a `build` script to `package.json`: `"build": "tsc"`.
2. Add a `start` script: `"start": "node dist/server.js"`.
3. Deploy to **Render.com** (Web Service). Set the environment variable `DATABASE_URL` to a Render PostgreSQL instance.
4. Render will automatically run `npm run build` and `npm start`.
